## Intended behavior

Add an OpenAI-compatible custom configuration alongside the existing integrations. The owner supplies a base URL or chat-completions URL, arbitrary model ID and optional saved API credential. Saving registers an immutable owner-scoped configuration without calling the endpoint, fetching its catalog or sending a completion. A saved configuration can be selected through the existing narrator/model controls. Configuration is not evidence that the endpoint is reachable or that its model obeys the narrator contract.

The owner subsequently said “không cần config giới hạn đâu” and explicitly rejected configuring limits. The Custom form therefore has only URL, model and optional key: no context/output-limit fields, price fields, billing selector, spending-cap form or extra billing consent. Use automatic conservative token defaults. Custom cost/quota is managed by the supplied endpoint, with unknown prices and explicit provider-managed provenance; do not label it verified/free or invent a zero-USD bill. Custom dispatch does not require a Playroom trial grant or spending-cap configuration. This latest user direction overrides older repository spending prerequisites only for the new custom integration. Existing OpenRouter/Ollama guards, current owner settings, provider consent and import review gates remain intact. No configuration action sends a story. Custom support initially targets narrator dispatch with the existing economy context assembly, not native structured context or consolidation support.

The adapter must pin the selected endpoint and model, omit OpenRouter routing extensions, support optional authentication, preserve cancellation and incomplete-stream rejection, and never automatically retry an uncertain generation. HTTP is allowed only for loopback; remote custom endpoints require HTTPS. Reject URL user information, query strings, fragments and control characters, and do not follow redirects. Secrets stay in the existing private credential store and never enter profile snapshots, toasts or Git.

## Review findings and regressions

Review found that adding a configuration/adapter alone left the context-preview API blocked by its old verified-pricing prerequisite. The custom path now needs explicit immutable, owner-configured metadata and application-default token-budget provenance through both preview and dispatch. It must not claim verified capabilities. The real custom wire is shared with the persisted request packer so the immutable payload hash matches the actual HTTP body, without OpenRouter routing fields or `stream_options`.

The authenticated integration regression uses the real application, generation runtime, default provider factory and custom adapter with an injected HTTP transport. It exercises keyed/keyless custom profiles under both existing cost-policy settings, then preview, generation, commit and application reload. It records zero provider calls during configuration and preview, one POST after explicit Send, pinned owner credentials only when present, matching wire hashes, unknown cost totals and no app trial authorization/reservation. The initial regression exposed loss of provider-managed cost provenance; after correction, root independently verified all four cases passing. A subsequent fixture assertion used the wrong credential-summary field and was corrected to the actual credential ID without changing production behavior.

The browser regression first failed against the baseline assets because the Provider select had no Custom option. A subsequent run revealed an overly broad accessible-label selector matching the loading section rather than the select; it was replaced with an exact combobox locator, retaining the normal automatic wait. No timeout increase or skipped assertion is part of that recovery.

Frontend review additionally requires the provider selector to remain usable after selecting Custom, neutral configured-model wording, no custom budget/pricing fields, safe retained-key handling when editing the endpoint, deterministic reopening when multiple custom profiles exist, and an actionable Economy-mode instruction for unsupported Quality selection. The new form must not inherit a saved key when its endpoint origin changes.

Those findings are addressed: successful saves prepend the new/updated profile and the server lists latest profile versions in newest-created order, with regression coverage for multiple custom IDs. Custom selections use a neutral API-settings action; Quality mode has an explicit Economy instruction. Key input clears after credential acknowledgement and is not resent if only the profile save must be retried. Retained credentials are cleared when the endpoint origin changes. An inherited oversized token budget no longer prevents selecting Custom: stored owner budgets remain intact, while the custom preview and worker use the same application defaults automatically. A negative adapter test also prevents an explicitly keyed profile from silently becoming keyless.
